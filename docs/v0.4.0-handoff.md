### Wrapper: correctness bug producing wrong scalar from mul-ct

The blocker on the demo producing the right answer. Symptom: a `joint-customer-overlap` execution on a 76-row dataset_a × 1-row dataset_b (where the 1 row of B is also in A) decrypts to 15235 in every slot instead of 1. The fact that all 16384 slots agreed on one wrong value proves the rotation/eval-sum logic is fine; the wrong scalar comes from upstream of the sum (mul-ct or relinearize). VS deployed wrapper revision `00028-xqc` with `reset-keys` before each execution + diagnostic logging in mul-ct/relinearize; the next demo run will either show the right answer or produce logs that name the wrong key tag. Repro execution ID was `2dce2344-12b1-4e4e-b944-689d7a30dbb8`.

### Platform: list-executions endpoint

Awaiting confirmation from VS of the actual path. Once confirmed, the script is already written to consume it (poll for `state=awaiting-release`, take the newest).

### Platform: hide FHE circuit from customer view

The endpoint `GET /api/functions/{slug}/{version}/definition` currently returns the full Firestore doc, leaking the `ops` (FHE circuit), `engine`, `engineProfile`, `requiredEvalKeys`, and `registry` fields. These are JuLenny IP and must not reach customers. The toolkit reads only `slug`, `version`, `cryptoContextSpec`, `inputs[]` (name/role/encoding/layout/schema/schemaParams), and `output.{name,layout}` - see `cli/src/commands/crypto.cpp:600-668`. Fix is to strip the proprietary fields before returning from this endpoint. The wrapper service reads Firestore directly (server-side) so it's unaffected; the admin UI has its own endpoint (`/api/admin/fhe-functions`) that can keep returning the full doc.

### Platform: surface execution failure + cost preview

(1) Surface execution failure reasons properly: failureReason field on the execution doc (VS reports this is done in revision 00034-sm4), audit log entry (also reportedly done), and UI rendering of both. (2) Cost preview before execute: `/api/grants/{id}/estimate` exists but isn't wired into the execute flow or surfaced in the demo's `05-run-query.sh`.
